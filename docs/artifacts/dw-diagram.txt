// pr-data · base de dados da rede: DW (dimensões e fatos) e as origens de cada tabela. Esboço v2.1, 20/10/2026.
// Cole em dbdiagram.io. MEDIDO = réplica pr-bko-read1 em 20/10/2026. ESTIMATIVA = a medir.
// Nomes pelo ADR 2026-10-20-lingua-nomes-e-glossario-do-dw e pelo glossário (notas/Glossário do DW). Chaves pelo ADR 2026-10-20-chaves-do-dw.
// Pares: esquema/mart-crm.dbml (o CRM como consumidor) e notas/Linhagem e origens do DW.md (fluxo e matriz de origens).

Project pr_data {
  database_type: 'PostgreSQL'
  Note: '''
  # pr-data · base de dados da rede (v2.1)
  Instância dedicada, fora da produção. Tipos em PostgreSQL (hipótese da prova); o modelo não depende do motor.

  **Camadas**
  - raw_<origem>: pouso 1:1 das origens, só com as colunas listadas aqui (grupos cinza), com o fuso de cada origem declarado.
  - dw: dimensões (azul), fatos (verde), perfis (roxo), configuração (amarelo).
  - dw_pii: dado pessoal em claro, acesso restrito (vermelho).
  - mart_<consumidor>: o que é de um consumidor só. Ver mart-crm.dbml.

  **Chaves** (ADR 2026-10-20-chaves-do-dw)
  - Toda tabela tem chave do DW; o id da origem nunca é a chave.
  - Entidade ou fato de uma linha de origem: <nome>_id = '<origem>:<id>' (produto_id = bko_estoque:123; lote_id = pinoquio_collection_form:98765; venda_produto_id = bko_nf_produto:555).
  - Nasce no DW: ULID (pessoa_id, uniao_pessoa_id). Catálogo: código de negócio (loja_id, marca_id, grupo_produto_id, categoria_id, tamanho_id). Perfil e retrato: chave composta do grão.
  - O fato guarda a chave durável da entidade, nunca a de uma versão: unir pessoas ou dar história a uma dimensão não reprocessa fato.
  - Chave de dimensão no fato nunca é nula: -1 / nao_identificado (a origem não diz quem) e -2 / nao_se_aplica (o papel não existe nesse fato).

  **Regras de ligação**
  - Fato aponta para dimensão. Dois processos se ligam pela dimensão compartilhada (dim_produto, dim_cadastro).
  - A chave de outro processo entra como dimensão degenerada (lote_id na entrada, nf_id na venda): agrupa e cruza, sem tabela de dimensão. Para cruzar, cada lado é somado até o grão comum antes da junção.
  - A única ligação entre dimensões é a classificação do produto (marca, grupo de produto, categoria, tamanho) e a do cadastro com a pessoa.
  - Id vindo da origem (bko_*, pinoquio_*, pr_notify_*) só aparece na tabela cujo grão ele é, como coluna de linhagem sem linha: serve para rastrear e recarregar.

  **Como ler as linhas**
  - Cinza claro com nome grao_*: a tabela do DW herda o grão daquela origem.
  - Cinza escuro: relações dentro das origens.
  - Verde: fato para dimensão. Verde claro com nome dd_*: dimensão degenerada (chave de outro processo). Azul: classificação do produto e cadastro para pessoa.

  **Fornecedor e cliente são papéis no fato** (cadastro_fornecedor_id, cadastro_cliente_id); o cadastro aponta para a pessoa.
  '''
}
